# MedSync UX Blueprint

## Instructions

1. Read `docs/02-design/README.md`.
2. Use product personas and journeys from `docs/01-product` as input.
3. If external references influenced the task, read `docs/01-product/REFERENCE_TRACEABILITY_MATRIX.md`.
4. Map every referenced product pattern to a MedSync screen, state, or explicit blocker.
5. Do not implement screens, components, CSS, routes, or frontend code.
6. Document wireframes in Markdown when visual assets are not approved.
7. Keep copy sober and avoid regulatory claims.
8. Reflect privacy and least privilege in every UX decision.
9. Do not let MedSync Care or Medical UX look like HR/admin software.

## Required references

- `docs/02-design/UX_GUIDELINES.md`
- `docs/02-design/WIREFRAMES.md`
- `docs/02-design/COPYWRITING_GUIDELINES.md`
- `docs/01-product/PERSONAS.md`
- `docs/01-product/USER_JOURNEYS.md`
- `docs/01-product/REFERENCE_TRACEABILITY_MATRIX.md`

## Output contract

- Identify affected profiles.
- Describe UX states covered.
- List reference patterns mapped to screens.
- Mark unvalidated visual decisions as `TODO`.
- Confirm no UI implementation was performed.
