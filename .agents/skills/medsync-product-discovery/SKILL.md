# MedSync Product Discovery

## Instructions

1. Read `docs/01-product/README.md`.
2. Read only the product document needed for the task.
3. If the task includes external references, read `docs/agentes/EXECUTION_GUARDRAILS.md` and update `docs/01-product/REFERENCE_TRACEABILITY_MATRIX.md`.
4. Convert each reference into capability, UX impact, backlog item, evidence expectation, or explicit blocker.
5. Preserve the status as Product Discovery unless formal approval exists.
6. Do not invent business rules, market facts, pricing, personas, or implementation details.
7. Mark unvalidated assumptions as `TODO`.
8. Keep the B2B privacy rule central: companies never access individual clinical data.
9. Update cross-links when creating or renaming product documents.
10. Never call a reference "incorporated" unless it is traced to backlog and status.

## Required references

- `docs/01-product/PRODUCT_VISION.md`
- `docs/01-product/BUSINESS_MODEL.md`
- `docs/01-product/B2B_MODEL.md`
- `docs/01-product/REFERENCE_TRACEABILITY_MATRIX.md`
- `docs/14-roadmap/REFERENCE_ALIGNED_IMPLEMENTATION_PLAN.md`
- `docs/01-product/SPRINT_1_REPORT.md`

## Output contract

- State which product files were read.
- List created/updated documents.
- List open `TODO` decisions.
- List references mapped to backlog and implementation status.
- Confirm no code/API/database changes were made.
